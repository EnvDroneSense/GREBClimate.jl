Configuration

A run is described by a Config and its length by a RunSpec. Build a Config from a named experiment with preset, or from its parts:

PartTypeDecides
scenarioScenarioWhat the experiment imposes: CO₂ path and where it applies, sunlight, surface forcing, control CO₂, start year, output form
processesProcessesWhich physical processes run, each with a stated meaning when off
hydrologyHydrologyThe evaporation and rain scheme
correctionsCorrectionsHow the flux corrections are obtained: SpinUp(years), Stored(), NoCorrections()
config = preset(:co2_double)                                   # a named experiment
config = preset(:co2_double; processes = (clouds = :uniform,))  # with one process changed
config = Config(scenario = Scenario(co2 = ConstantCO2(500)))    # from parts

Every part validates its options when it is built, so a misspelt option fails at once instead of being ignored. The option tables below are the types' own documentation.

Three presets take a parameter: preset(:obliquity; index = ...) and preset(:eccentricity; index = ...) pick the table row (default: the row nearest today), preset(:earth_sun_distance; percent = ...) the distance change, preset(:custom_co2; path = ...) the CO₂ file. :decon_mean_climate is the mean-climate deconstruction: switch processes off with processes = (...) and run it with RunSpec(scnr = 0). On its stored corrections a switched-off process changes the climate; a spin-up would recompute the corrections for each configuration and pull every one back to the observed climate. :decon_2xco2 is the 2×CO₂-response deconstruction. Both run the MSCM physics (mscm_hydrology(), no moisture convergence), which the deconstruction switches were designed for: with the default hydrology some switches make the run diverge, for example vapor_diffusion = false on the stored corrections or humidity = :uniform.

Writing a scenario from parts

A Scenario combines one part of each kind; any combination runs.

julia> s = Scenario(co2 = CO2Step(340, 680, 2000), solar = SolarCycle(2, 11), control_co2 = 340);

julia> r = resolve(Config(scenario = s));

julia> forcing(1, 1999, r).CO2, forcing(1, 2000, r).CO2
(340.0f0, 680.0f0)
KindOptions
CO₂ path (CO2Path)ConstantCO2, CO2Table, CO2File, A1BRamp, CO2SineWave, CO2Step, SeasonalCO2
Where it applies (CO2Mask)UniformMask, LatitudeMask, SurfaceMask
Sunlight (Solar)ModernSolar, SolarConstant, SolarCycle, SolarTable, EarthSunDistance
Surface (SurfaceForcing)NoSurfaceForcing, BoundaryAnomaly, SSTOffset

A scenario that reads a table (CO2Table, CO2File, SolarTable) loads it when the configuration is resolved: greb_model! does this itself, from its jld2_dir.

To compare several configurations, pass them as a list to run_ensemble; the Tutorial shows how.

Configuration types

GREBClimate.Config — Type
Config(; scenario=Scenario(), processes=Processes(), hydrology=Hydrology(),
         corrections=SpinUp(3))

Everything a run needs besides its length (RunSpec) and the data: what the experiment imposes (Scenario), which physics runs (Processes), the hydrology scheme (Hydrology), how the flux corrections are obtained (Corrections). The default is the full model under constant 340 ppm. Build named experiments with preset.

source
GREBClimate.RunSpec — Type
RunSpec(; ctrl=1, scnr=1)

Run lengths in years for greb_model!: ctrl (control run) and scnr (scenario run). The spin-up length is part of the configuration (SpinUp).

julia> RunSpec(ctrl = 10, scnr = 30)
RunSpec(10, 30)
source
GREBClimate.preset — Method
preset(name; processes=nothing, hydrology=nothing, corrections=nothing,
       index=nothing, percent=0, path="") -> Config

The Config of a named experiment (preset_names lists them). processes and hydrology change the preset's physics: a NamedTuple such as (ocean = :none,) changes those options, a Processes or Hydrology replaces them. index selects the table row of :obliquity/:eccentricity (default: the row nearest today, see SolarTable), percent the distance change of :earth_sun_distance, path the CO2 file of :custom_co2.

Every preset runs the default physics with a 3-year SpinUp, except the two deconstructions, which run the MSCM physics (mscm_hydrology, moisture_convergence = false) their switches were designed for. :decon_mean_climate (mean-climate deconstruction; run it with RunSpec(scnr = 0)) also takes the Stored corrections, so a switched-off process changes the climate. :decon_2xco2 is the 2×CO2-response deconstruction.

julia> preset(:co2_double).scenario.co2
ConstantCO2(680.0f0)

GREBClimate.Corrections — Type
Corrections

How the flux corrections that hold the control climate at the observed one are obtained: SpinUp(years) computes them, Stored() reads the dataset's file, NoCorrections() runs without.

The corrections belong to the configuration they were computed for. The default hydrology (fitted rain, moisture convergence) is only stable on corrections from a spin-up of the same configuration: on other corrections, or none, humidity can build up without limit where the air rises and the run diverges within years.

source
GREBClimate.Hydrology — Type
Hydrology(; rain=:fitted, rain_fit=:era, evaporation=:original)

The evaporation and rain scheme. The default is the fitted scheme of Stassen et al. (2019); mscm_hydrology gives the original GREB scheme.

KeywordValues
rain:fitted (Stassen et al. 2019), :original (proportional to humidity), :rh (+ relative humidity, with a minimum rain rate), :omega (+ vertical velocity), :rh_omega
rain_fit:era, :ncep: which reanalysis the :fitted coefficients were fitted to; only for rain = :fitted
evaporation:original (climatological wind plus a fixed gust term), :skin (skin temperature, land/ocean exchange coefficients), :original_gust (:original with larger gust terms and land/ocean coefficients), :skin_gust (wind-speed climatology with its own gust terms and land/ocean coefficients; no skin temperature)
source
GREBClimate.NoCorrections — Type
NoCorrections()

Run without flux corrections; the control climate drifts from the observed one.

source

Processes(; kwargs...)

Which physical processes run. Every option says what the model does instead when a process is off. The default is everything on, with the observed climatologies.

GREBClimate.SpinUp — Type
SpinUp(years)

Compute the flux corrections in a spin-up of years years before the control run. SpinUp(0) runs no spin-up and uses whatever corrections fields already holds.

source
GREBClimate.Stored — Type
Stored()

Use the flux corrections stored in the dataset instead of computing them. They were computed with the MSCM physics (mscm_hydrology, moisture_convergence = false) and hold that configuration at the observed climate. With the default hydrology the control drifts (about 5 K in 20 years); use SpinUp there.

greb_model! reads them from jld2_dir when it is given, and a missing file is an error there. Without jld2_dir it uses the corrections already in fields, which load_climatology loads.

source
GREBClimate.mscm_hydrology — Method
mscm_hydrology()

The original GREB hydrology: Hydrology(rain = :original, evaporation = :original). Reproducing MSCM also needs Processes(moisture_convergence = false).

source
GREBClimate.A1BRamp — Type
A1BRamp()

The SRES A1B path: 310 ppm in 1950, 370 in 2000, 520 in 2050, 700 in 2100, linear in between; 340 ppm after 2100.

source
GREBClimate.BoundaryAnomaly — Type
BoundaryAnomaly(source)

Anomalies of surface temperature, winds and vertical velocity added to the climatology for the scenario, with surface temperature held at it: source is :cmip5_rcp85, :elnino or :lanina.

source
GREBClimate.CO2File — Type
CO2File(path)

CO2 per year from a text file of year ppm lines (see load_co2_custom).

source
GREBClimate.CO2Mask — Type
CO2Mask

Where the scenario CO2 applies; elsewhere the cell gets half of it (the regional 2×CO2 experiments): UniformMask, LatitudeMask, SurfaceMask. A mask acts on the scenario only; the spin-up and the control run on the control CO2 everywhere.

source
GREBClimate.CO2Path — Type
CO2Path

The scenario's CO2 concentration over time: ConstantCO2, CO2Table, CO2File, A1BRamp, CO2SineWave, CO2Step, SeasonalCO2.

source
GREBClimate.CO2SineWave — Type
CO2SineWave()

340 to 680 ppm in a 30-year cosine cycle: 510 + 170 cos(2π (year - 13) / 30).

source
GREBClimate.CO2Step — Type
CO2Step(before, after, year)

before ppm until year, after ppm from year on.

source
GREBClimate.CO2Table — Type
CO2Table(key)

CO2 per year from the dataset's IPCC table key: :rcp26, :rcp45, :rcp60, :rcp85, :ssp119, :ssp126, :ssp245, :ssp460, :ssp585 or :hist (1850-2017).

source
GREBClimate.ConstantCO2 — Type
ConstantCO2(ppm)

The same CO2 concentration for the whole scenario.

source
GREBClimate.EarthSunDistance — Type
EarthSunDistance(percent)

The Earth-Sun distance changed by percent percent of today's; positive is further away. Insolation scales with the inverse square, so percent = 1 gives about 2 % less sunlight.

source
GREBClimate.LatitudeMask — Type
LatitudeMask(band)

The scenario CO2 applies in band: :nh, :sh, :tropics or :extratropics.

source
GREBClimate.ModernSolar — Type
ModernSolar()

Present-day insolation from the dataset.

source
GREBClimate.NoSurfaceForcing — Type
NoSurfaceForcing()

No imposed surface forcing.

source
GREBClimate.SSTOffset — Type
SSTOffset(offset)

Ocean surface temperature held at the climatology plus offset K, with CO2 at its control value.

source
GREBClimate.Scenario — Type
Scenario(; co2=ConstantCO2(340), co2_mask=UniformMask(), solar=ModernSolar(),
           surface=NoSurfaceForcing(), control_co2=340, start_year=1950, output=:anomaly)

What an experiment imposes. control_co2 is the CO2 of the spin-up and the control run; co2 the scenario's. start_year is the calendar year the scenario starts in; output is :anomaly (each month minus the control's final year) or :absolute.

source
GREBClimate.SeasonalCO2 — Type
SeasonalCO2(in_season, out_of_season, season)

in_season ppm during season, out_of_season ppm for the rest of the year. :boreal_winter is 1 October through the first step of 1 April (steps 547-730 and 1-181), half the year, :boreal_summer is April to September.

source
GREBClimate.Solar — Type
Solar

The incoming sunlight: ModernSolar, SolarConstant, SolarCycle, SolarTable, EarthSunDistance.

source
GREBClimate.SolarConstant — Type
SolarConstant(offset)

The solar constant raised from 1365 by offset W/m².

source
GREBClimate.SolarCycle — Type
SolarCycle(amplitude, period)

The solar constant varying as 1365 + amplitude sin(2π year / period) W/m².

source
GREBClimate.SolarTable — Type
SolarTable(kind, index)

Insolation from the dataset's solar scenario tables: kind is :paleo (231 kyr ago), :obliquity or :eccentricity; index selects the table row of the last two. Obliquity row k is -25 + k/2 degrees (k = 0, 5, ..., 230), eccentricity row k is -0.30 + 0.01k (k = 0, ..., 60; negative puts perihelion in July). The default is the row nearest the present-day orbit: 95 (22.5 degrees) and 32 (0.02).

source
GREBClimate.SurfaceForcing — Type
SurfaceForcing

A forcing imposed on the surface during the scenario: NoSurfaceForcing, BoundaryAnomaly, SSTOffset.

source
GREBClimate.SurfaceMask — Type
SurfaceMask(surface)

The scenario CO2 applies over :ocean or over :land_ice, as the control run's annual-mean ice cover defines them. A scenario with this mask needs a control run: RunSpec(ctrl = 0) is an ArgumentError.

source
GREBClimate.UniformMask — Type
UniformMask()

The scenario CO2 applies everywhere.

source
GREBClimate.ResolvedConfig — Type
ResolvedConfig

A Config with the data its names refer to: config, hydrology (a ResolvedHydrology), co2_table (year => ppm, empty unless the scenario's CO2 comes from a CO2Table or CO2File) and solar_table (the SolarTable insolation, or nothing). Build it with resolve; greb_model! does so itself.

source
GREBClimate.ResolvedHydrology — Type
ResolvedHydrology

A Hydrology scheme with its rain-regression coefficients c_q, c_rq, c_omega, c_omega_std; what hydro! reads. Build it with resolve(hydrology).

source
GREBClimate.resolve — Method
resolve(config::Config; jld2_dir="") -> ResolvedConfig
resolve(hydrology::Hydrology) -> ResolvedHydrology

Replace the names in config with what they refer to: the rain coefficients of its hydrology scheme, and the CO2 or solar table its scenario reads from the dataset in jld2_dir (or from the user's CO2 file).

julia> resolve(mscm_hydrology()).c_q
1.0f0
