Fortran comparison

benchmark/fortran/run_fortran_comparison.jl checks GREBClimate.jl against the original Fortran GREB and times both on the same workload (3 flux-correction, 3 control and 50 scenario years, co2_double). It builds three gfortran executables, runs them, and runs Julia in a child process. It is not part of the test suite, so it stays in benchmark/. The flags of the other harnesses are in Benchmarks.

ModeDoes
compare (default)Runs verify, then times official, native, control and Julia in shuffled trials ([reps], default 3)
verifyThe gate: do both models give the same scenario temperatures (about 1 minute)
memoryPeak memory of each build and Julia (Windows only, 1 rep)
ioThe cost of the Fortran's output writes
buildCompiles the three Fortran builds
selftestThe script's own logic; needs no compiler
driverThe Julia run, started by the other modes in a child process

Set-up

It runs in the package environment, from the repository root:

julia --project=. benchmark/fortran/run_fortran_comparison.jl [mode] [reps]
VariableMeaningDefault
GREB_GFORTRANPath to gfortrangfortran on PATH, then the Scoop MinGW folder
GREB_FORTRAN_DIRThe Fortran source treeA folder greb-official-official next to the repository, one level up, or in a sibling data folder
GREB_FORTRAN_EXPFortran EXP number; the Julia preset follows it20 (co2_double)
GREB_BENCH_DIRBuild and run treegreb_fortran_bench in the temp folder
GREB_DATAJulia input dataThe repository dataset

Missing gfortran or source tree stops every mode except selftest with exit code 1 and a line naming what is missing.

The gate

verify runs the Fortran and Julia once, untimed, and compares the monthly scenario Ts. compare runs it first and prints no timings when it fails.

Self-check (control / official, identical builds): 0.986x  ok

The figures come from a noisy machine (the run printed NOISY) and show the layout, not results. compare prints the machine state before and after, like the other harnesses, and appends one row per variant to benchmark/results/<date>.csv with mode fortran.

BuildFlags
official-Ofast -ffast-math -funroll-loops -fopenmp (the original script)
nativethe same plus -march=native
controla second copy of official, the self-check

Rules

RuleWhy
Run verify before quoting any timingTwo models that disagree have no meaningful speed ratio
Discard a run whose self-check is more than 5 % from 1.00control and official are identical builds, so the machine was noisy
The Julia time is a fresh processStart-up, package load and compilation are inside it: an end-to-end figure, not a kernel timing
The Fortran also writes about 88 MBUse io to bound what that costs
Exit code 1 means the mode failedMissing tooling, a failed gate or a failed self-check
