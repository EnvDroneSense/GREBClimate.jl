Profiling

benchmark/profile.jl shows where the time and the memory of a run go. Benchmarks say how much time there is; the profiler says which function and line holds it. It runs in the package environment and needs no extra packages, except for the two optional modes below. The full list of flags is in benchmark/README.md.

ModeMeasures
step (default)Sampled control runs of :full_model (25 simulated years each, repeated until 10000 samples): where the time loop spends its time
setupThe same with 1-year runs: what one greb_model! call costs besides the time loop
allocsEvery allocation of one 1-year run, by function and line
dispatchWhether a call in one model step is dispatched at run time (static; needs JET.jl in the default environment)
compareThe change in shares between two step or setup runs

In the REPL

Start Julia with one thread in the package environment, load the file and call main. Loading defines main and runs no mode. This file and run_benchmarks.jl both define main, so use one per session. From a shell the same run is julia --project=. -t 1 benchmark/profile.jl step --years=1 --samples=500.

julia> include("benchmark/profile.jl")

julia> main(["step", "--years=1", "--samples=500", "--out=run-a"])

main returns the exit code, which is the 0 at the end. This run is short (675 samples, where the default takes 10000) and is shown for the layout, not as a result: the profiler warns below 5000 samples. The screen shows the top eight rows of each table; report.md in the run's folder has all of them.

Reading the report

SectionRead it for
By classWhat kind of time there is: vectorized kernel, Base array access, package code, allocation and GC, copies, dispatch, compilation, waiting, file I/O
By functionWhich function owns the time. A sample belongs to the innermost frame in src/, so library time is charged to the line that called it
By lineWhich line of the model owns the time
Largest frames (report.md only)Under the class table: the frames of each class and the function each is charged to

The other files of a step or setup run:

FileContent
counts.tsvSelf samples of every class, function and line, uncut, as table, row, value columns; compare reads it
tree.txtThe call tree from greb_model! down, rows below 0.1 percent left out
flat.txtSelf time per frame, libraries included
stacks.foldedOne line per distinct stack, for flame graph tools (speedscope, FlameGraph, inferno)
profile.pb.gzThe same samples in pprof format, with --viewer=pprof (needs PProf.jl in the default environment)

Reports go to benchmark/profiles/<date>-<commit>-<mode>/, which is git-ignored, or to --out.

## By function

| Row             |   A % |   B % |  Diff |  +/- | 3 SE |
|:----------------|------:|------:|------:|-----:|-----:|
| `circulation!`  |  9.93 |  7.19 | -2.74 | 1.63 |      |
| `_advection!`   | 29.04 | 31.14 | +2.10 | 2.71 |      |
...

A run is a report directory or its name under benchmark/profiles/. Rows are sorted by the size of the change; a * in the last column marks a difference of three standard errors or more. A row one run lacks counts as zero there. A run made before counts.tsv existed must be profiled again.

Errors

An unknown mode, a flag the mode does not take, a second positional argument, a missing dataset and a missing counts.tsv stop the run, with exit code 1 from a shell:

julia> main(["step", "--yeers=1"])
ERROR: the step mode takes no --yeers flag

Rules

RuleWhy
Run at -t 1On Windows the sampler records the first thread only, so at -t 2,0 one of the two circulation! calls is missing
Take 5000 samples or moreThe sampler's rate varies from 2 to 13 ms per sample; the script repeats the run up to the target and warns below 5000
A row smaller than three standard errors is noiseThe same holds for the Diff column of compare
A share is the ceiling of a gain, not a gainA profile shows where the time goes. Show that a change is faster with compare_kernels (see Benchmarks)
When one row grows, the other shares fallIn compare, read the row that rose and ignore the rest
A @turbo loop is one rowThe whole loop is charged to its @turbo for line; lines inside it are not resolved
